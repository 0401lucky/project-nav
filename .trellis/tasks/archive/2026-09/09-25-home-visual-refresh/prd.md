# 首页视觉调整

## Goal

让首页看起来是有意设计的：内容和壁纸不打架，书签一眼就能找到、认得出来。性能优先于颜值，改动不能让首页变慢。

## 已确认事实

来源：用户 2026-09-25 的截图、2026-09-27 只读导出的线上数据快照（`mockups/shared/data.js`，52 条书签、31 个图标），以及代码。行号以当前 main（`82e2766`，已含交互任务的改动）为准。

- **布局和壁纸冲突**：内置壁纸是按「人物在右、左侧留空」生成的（原设计文档 §8），但分组面板铺满整个宽度（`src/components/home/BookmarkGrid.vue:33-36`），人物被一层层半透明毛玻璃盖住，只从面板缝隙里露出来。
- **小分组也独占一整行**：线上 9 个分组，卡片数分别是 7、6、9、1、4、2、6、16、1。「上游网关」「工具」都只有 1 张卡片，却各占一条横贯整屏的面板。卡片按 `auto-fill minmax(150px, 1fr)` 排列（`GroupPanel.vue:180-184`）。
- **同名卡片分不清**：卡片只显示标题，标题直接来自网页 `<title>`，两行截断（`BookmarkCard.vue:322-333`）。线上有 6 张「CLI Proxy API Management Center」、2 张「NewAPI Middleware Tool」、2 张「Cloudflare 临时邮件」；另有 2 张「我的 API 店铺 · …」前半截相同。其中 2 对连主机名都相同：`cpa-codex.lucky0506.shop` 的 `#/login` 与 `#/plugin-store`，`mail.lucky04.dpdns.org` 的首页与 `/admin`。
- **首字色块取字有误**：取标题的第一个字符，不转大写，也不跳过符号（`src/components/ui/FallbackIcon.vue:31`）。「lucky API」显示成像 I 的小写 l，「（codex2）CPA Manager Plus」显示成「（」。色相由域名哈希决定、饱和度固定 55%（`FallbackIcon.vue:16-28`、`:40`），一排彩虹色和真实图标混在一起显得乱。
- **部分真实图标观感差**：Google AI Studio 的图标是黑色线条加透明底，在深色卡片上几乎看不见；「叙说·春信」「米饭机」是照片式 logo，缩到 32px 后像一张小照片。
- **按钮主次颠倒**：最常用的「新增」书签是右上角一个小胶囊（`TopBar.vue:18`），很少用的「新建分组」反而是右下角最醒目的黄色悬浮按钮（`App.vue:250-255`）；每个分组头都常驻「添加」「编辑」两个文字按钮（`GroupPanel.vue:65-66`）。「设置」已经是图标按钮。
- **层次发灰**：卡片底色 6% 白、面板底色 8% 白（`src/styles/tokens.css:11-12`），再叠一层 20px 模糊（`GroupPanel.vue:108`）。
- **性能相关**：每个分组面板各有一层 backdrop-filter，线上 9 个分组就是 9 块大面积模糊层，而且都随列表滚动。原项目约束允许这样用，但层数越少越省。

## Requirements

### 布局：B「玻璃启动器」（用户 2026-09-28 选定）

视觉以样稿 `mockups/b.html` 为准（双击即可打开，右下角工具条可换壁纸）。

- **R1 左侧启动器面板**：桌面端把顶栏、搜索框、分组列表全部装进左侧一块面板，右侧整块留给壁纸人物。面板本身固定不动，书签列表在面板内部滚动。样稿宽度为 `clamp(620px, 62vw, 980px)`，1440 宽时约 890px。
- **R2 全页只有一层模糊**：只有这块面板用 backdrop-filter（样稿默认开启，24px）；分组不再有自己的底色和模糊层。线上从 9 层降到 1 层，且这一层不随滚动移动。弹出菜单、弹窗沿用现有的模糊，不算在内。
- **R3 分组多列错落**：面板内的分组按列错落排，宽度够时排 3 列（每列最小约 220px），1 张卡片的分组不再独占一整行。
- **R4 书签改成紧凑列表**：一行一条，图标 22px，标题单行截断；悬停时右侧出现「⋯」菜单按钮（沿用现有交互）。
- **R5 按钮主次**：顶栏「新增」改为强调色实心的主按钮；「新建分组」从右下角的黄色悬浮按钮挪到分组列表末尾，改成虚线的次要入口；分组头的「添加」「编辑」改为图标按钮，桌面端悬停才出现，触屏上常显。
- **R6 窄屏（≤ 640px）**：面板铺满全屏，模糊降一档；分组单列；卡片保持固定 3 列、竖排（图标在上、标题在下）。
- **R7 首字色块取字**：取标题中第一个字母、数字或汉字并转大写，跳过括号等符号（样稿已按此实现）。

### 同名书签：重复时显示主机名（用户 2026-09-28 选定）

- **R8 同名时显示主机名**：书签标题和任意另一张书签重复时（判重范围是全部书签、不限同一分组；去掉首尾空白、不区分大小写后相同即算重复），在标题下方用一行小号灰字显示主机名，去掉开头的 `www.`。标题不重复的书签不显示，仍是一行。判重按全部书签算，搜索过滤时主机名行不会跟着输入忽隐忽现。
- 主机名也相同的 2 对（`cpa-codex.lucky0506.shop` 的 `#/login` 与 `#/plugin-store`，`mail.lucky04.dpdns.org` 的首页与 `/admin`）不做自动处理，由用户每对改一张标题；改完后标题不再重复，这几张也就不再显示主机名。

### 首字色块配色：低饱和（用户 2026-09-28 选定）

- **R9 低饱和、同站同色**：色相仍由域名哈希决定（同一个站永远同一个颜色），底色压暗、字母带同色调，对应样稿「色块 → 低饱和」：底色 `hsl(色相 26% 28%)`，字母 `hsl(色相 55% 84%)`。

### 深色透明图标：反白（用户 2026-09-28 选定）

- **R10 服务端反白**：图标转码时，如果图标大片透明、不透明部分又黑又没有彩色，就把颜色反成白色，透明部分不变；对下载、上传、公共服务三条来源一视同仁。按线上 31 个图标实测，这条规则只命中 DEEIX Chat 和 Google AI Studio；带白色或彩色主体的偏暗图标（Narra Image、我的 API 店铺、Resend）不受影响。对应样稿「深色图标 → 反白」。
- 已经存在的这 2 个图标不自动迁移：上线后在它们的编辑框里各点一次「重新抓取」，按新规则重新处理。

## Acceptance Criteria

- [x] 1440×900 下，面板右侧约 1/3 视口宽度内没有任何内容，四张内置壁纸的人物都完整露出
- [x] 桌面端首页常驻元素里只有一个带 backdrop-filter（弹出菜单、弹窗打开时除外）
- [x] 宽屏下只有 1 张卡片的分组（「上游网关」「工具」）和其他分组并排，不占满整行
- [x] 顶栏「新增」是首页上唯一的实心强调色按钮；右下角不再有悬浮按钮；「新建分组」在分组列表末尾
- [x] 分组头的「添加」「编辑」在桌面端悬停才出现，在窄屏常显
- [x] 窄屏（390×844）卡片固定 3 列，宽屏（1440×900）不是固定 3 列
- [x] 首字色块：「lucky API」显示 L，「（codex2）CPA Manager Plus」显示 C；配色为低饱和，同一主机名的色块颜色相同
- [x] 同名书签：6 张「CLI Proxy API Management Center」等标题重复的书签，标题下直接显示主机名；标题不重复的书签不显示
- [x] 深色透明图标：DEEIX Chat 与 Google AI Studio 在「重新抓取」后显示为白色图形，在深色面板上清晰可见；其余 29 个线上图标重新抓取后外观不变（本地通过共享转码链路、31 张原图及上传后像素验证；线上旧缓存待发布后手动重抓）
- [x] 首屏 JS gzip 仍 < 80KB，不新增运行时依赖，不引入 UI 库或动画库
- [x] 现有 e2e（27 条）与单测（242 条）全部通过（本轮含新增共 263 条单测）
