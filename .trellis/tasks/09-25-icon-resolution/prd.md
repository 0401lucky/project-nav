# 书签图标解析修复

## Goal

站点提供了图标的，都要能抓到；抓不到的，要让用户知道原因，并且有办法补上。

## 已确认事实

线上逐条诊断见 `research/production-icon-diagnosis.md`。27 条缺图标的书签按根因分为：

| 根因 | 条数 | 代码能否解决 |
| --- | --- | --- |
| sharp 不支持 ICO | 9（另有 EVE Chat 也会被 ICO 兜底救回） | 能 |
| 属性值解析把 data URI 截断 | 2 | 能 |
| `<link>` 里 `href` 写在 `rel` 前 | 1 | 能 |
| 站点本身没有图标 | 6 | 不能自动解决 |
| 站点已失效（404、526、DNS 不存在、超时） | 8 | 不是图标问题 |
| Cloudflare 质询（linux.do） | 1 | 服务端直抓无解 |

修好三类代码缺陷后，能自动拿到图标的书签从 26 条增加到 37 条（雨读的图标是含文字的 SVG，按 R10 跳过，需手动上传）。

流程上还有这些缺口：
- 手动新增时图标候选默认不选中，不点就不下载（`src/components/panels/BookmarkForm.vue:27`、`:121`、`:187`）；候选由浏览器预览，而浏览器能显示 ICO，于是出现「预览有图标、保存后没有」。
- 编辑面板不抓取、不显示图标区（`BookmarkForm.vue:49`、`:172`），已有书签没法重抓或换图标。
- 保存后前端不刷新图标状态（`src/stores/data.ts:167-178`），失败时没有任何提示。

## Requirements（草案）

- **R1 解码 ICO**：支持 ICO 容器里的 PNG 条目和 32 位 BMP 条目，取尺寸最大的一张；不新增依赖。现状：`server/lib/icons.ts:51` 直接交给 sharp，sharp 不认 ICO 容器。
- **R2 解析 `<link>`**：属性顺序无关；支持双引号、单引号和无引号三种属性值写法；data URI 完整保留；正确读取 `sizes`；认出 `rel="alternate icon"`。现状见 `server/lib/scraper.ts:161-162`。
- **R3 候选排序**：页面声明的图标（apple-touch-icon、icon、shortcut icon，按尺寸从大到小）排在 og:image、twitter:image 之前。现状：`scraper.ts:180` 让 og:image 排在 icon 前面（线上暂未踩到，GitHub 可复现）。
- **R4 按文件头识别图片**：不只看 Content-Type，按文件内容识别 PNG、JPEG、GIF、WebP、SVG、ICO。现状见 `icons.ts:166-167`。
- **R5 新增时默认带图标**：抓到候选后默认选中最合适的一个，用户仍可改选或取消。
- **R6 编辑时可重抓**：编辑面板能重新抓取图标，并显示结果；失败时给出可读的原因（页面 404、超时、域名解析失败、Cloudflare 质询、站点没有提供图标等）。
- **R7 批量补抓**：设置里一键重抓所有缺图标的书签，结束后给出成功与失败的统计，以及每条失败的原因。用于修复上线后补齐现有的 27 条。
- **R8 图标到位后自动刷新**：保存、重抓、补抓完成后，卡片上的图标自动更新，不需要刷新页面。
- **R9 手动指定图标**（已定：方案 C）：
  - 编辑面板可以上传或粘贴图片作为图标，走同一套转码（64px WebP）。
  - 编辑面板提供「从公共服务获取」按钮，**只有用户点击时**才由服务器请求第三方图标服务（Google `s2/favicons`，sz=128）；自动抓取、批量补抓都不访问第三方。
  - 第三方返回 404 时提示「公共服务也没有这个站的图标」。
- **R10 带文字的 SVG**（已定：跳过）：服务器容器里没有字体，SVG 里的 `<text>` 会渲染成方框（雨读、EVE Chat 实测）。含 `<text>` 的 SVG 候选直接跳过、试下一个；不在镜像里装字体。EVE Chat 由 `/favicon.ico` 兜底拿到，雨读需手动上传。

## Acceptance Criteria（草案）

- [ ] 部署后对线上数据批量补抓：ICO 的 9 条、EVE Chat、Zeabur 共 11 条自动拿到图标；雨读因含文字 SVG 被跳过，手动上传后有图标
- [ ] 编辑面板可上传/粘贴图片作为图标；点「从公共服务获取」能为 linux.do 拿到图标；未点击时服务器不访问任何第三方图标服务
- [ ] 含 `<text>` 的 SVG 候选被跳过，不会存成方框图标
- [ ] 单元测试覆盖 ICO 解码（PNG 条目、32 位 BMP 条目、alpha 全为 0 时退回 AND 掩码）
- [ ] 单元测试覆盖 `<link>` 解析（`href` 在前、无引号、单引号、含单引号的 data URI、`sizes` 排序、`alternate icon`）以及 icon 排在 og:image 之前
- [ ] 新增书签时贴完网址、不做任何点选就保存，卡片也会在几秒内换上图标
- [ ] 编辑已有书签可以重新抓取；失败时面板里显示具体原因
- [ ] 批量补抓结束后显示成功数、失败数和每条失败原因
- [ ] 没有新增运行时依赖

## Out of Scope

- 服务端无头浏览器渲染：由 JS 在运行时插入的图标拿不到，这类站点按「站点没有提供图标」处理。
- 存活检测：失效的站只在抓取结果里给出原因，不做主动巡检。
- 旧站 JSON 里的 `icon` 字段（`server/lib/legacy.ts:8-9` 目前直接丢弃）：线上数据已经导入完毕，这次不处理。
